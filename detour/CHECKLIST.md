# DETOUR · 100-step checklist

This is the live branch checklist. The ten phases and 001–100 IDs follow the planning PDF. Update the work or test detail when evidence warrants it and preserve stable IDs. Check a box only when its pass condition is verified, with evidence in that step and the latest [progress entry](PROGRESS.md). An unchecked item can be pending, in progress or blocked; record that detail in progress. Independent later steps may proceed around a documented dependency.

Start with [master direction](README.md). Resume using [progress](PROGRESS.md) and [continuation instructions](CONTINUE.md). Release evidence lives in the [submission report](submission-report/README.md).

## 02 · Concept definition and signature interaction

- [x] **011. Write the behavior thesis**
  - **Objective** — Make the promise understandable in one sentence.
  - **Work** — Use the working premise: hold where you are, explore another moment, then return in one action. Sketch one before and after using a standard seek bar.
  - **Deliverable** — One-sentence thesis and two frames.
  - **Pass condition** — A reviewer can describe the action without relying on the name or help text.
  - **Evidence** — [Behavior thesis and idle/held frames](design/PLAN.md#scope-and-behavior)

- [x] **012. Storyboard the five-second reveal**
  - **Objective** — Show the full action with real time values.
  - **Work** — Start paused at 00:42. Choose Keep my place, seek to 00:18, then Return to 00:42. Plan an extended shot with a second seek and a separate Stay here outcome.
  - **Deliverable** — Five-second storyboard plus a longer proof shot.
  - **Pass condition** — The held 00:42 remains legible through both seeks. Playback time visibly returns to 00:42.
  - **Evidence** — [Short storyboard and longer proof](design/PLAN.md#scope-and-behavior) and [real seek trace](submission-report/EVIDENCE.md#2026-11-15-first-prototype)

- [x] **013. Define the entry action**
  - **Objective** — Make creating a held place deliberate and discoverable.
  - **Work** — Prototype an exposed Keep my place button with a pin-shaped silhouette and a text label. Sample actual currentTime on press. Keep regular play/pause and the standard seek bar present.
  - **Deliverable** — Idle and just-held prototypes.
  - **Pass condition** — One press records the current point without a seek, pause or focus loss. The command is legible at 240 px.
  - **Evidence** — [Narrow keyboard and place-action checks](submission-report/EVIDENCE.md#2026-11-15-first-prototype)

- [x] **014. Define return and stay**
  - **Objective** — Give users a reversible move and a clean exit.
  - **Work** — Use Return to [time] to request a real seek and Stay here to clear the mark. Keep only one mark. Keep action text visible and use text or shape as well as color.
  - **Deliverable** — Action copy and interactive flow.
  - **Pass condition** — Return changes playback time once. Stay clears only the mark. No equivalent wording hides a different action.
  - **Evidence** — [Real return and stay tests](tests/browser.test.mjs)

- [x] **015. Pressure-test the problem**
  - **Objective** — Identify where holding a place benefits users.
  - **Work** — Write scenarios for a missed detail in an interview, instructor cross-reference, sports replay and film callback. Include a passive short clip where the feature will rarely be used.
  - **Deliverable** — Scenario grid with a counterexample.
  - **Pass condition** — At least three use cases have an observable task benefit. The passive clip retains ordinary unobtrusive controls.
  - **Evidence** — [Interview, tutorial, sports and passive watching tasks](design/PLAN.md#scope-and-behavior)

- [x] **016. Check media independence**
  - **Objective** — Keep the interaction independent of specially edited footage.
  - **Work** — Design the same five-second task for a captioned interview and a chapterless animation. Assume zero thumbnails, chapter data, transcript or analysis.
  - **Deliverable** — Two media-independent interaction scripts.
  - **Pass condition** — The button, origin, seeks and return all make sense without any authored metadata.
  - **Evidence** — [Captioned and chapterless rehearsal scenarios](design/PLAN.md#scope-and-behavior)

- [ ] **017. Test language and recognition**
  - **Objective** — Measure discoverability before committing expensive polish.
  - **Work** — Ask five uncoached users to identify the action in a two-second active-state crop. Give five a find-and-return task on a rough prototype, including at least two touch runs; record first click and time.
  - **Deliverable** — Small-sample results with video or notes.
  - **Pass condition** — At least 4 of 5 identify return and 4 of 5 complete the task in 10 seconds. Iterate once on failure, then reassess.
  - **Progress** — [Study protocol and crops ready. Five uncoached observations per task remain open.](design/FIRST-USE.md)

- [x] **018. Choose a visual signature**
  - **Objective** — Make the held origin recognizable inside the player crop.
  - **Work** — Use a bracket-shaped origin mark and a rectangular Return ticket aligned with the conventional rail. Compare it against a text-only mock and choose after cropping at 320 and 768 px.
  - **Deliverable** — Two crops and a recorded design choice.
  - **Pass condition** — The chosen crop shows current playhead and held origin as distinct shapes without a page title.
  - **Evidence** — [Player-only A/B crops and decision at 320 and 768 px](design/PHASE-2.md#visual-signature)

- [x] **019. Build a backup proof sketch**
  - **Objective** — Keep a practical fallback within reach.
  - **Work** — Sketch Pausepoint with a future-time stop marker, a regular seek bar and a keyboard-operable time picker. Test crossing during ordinary play versus seeking, then estimate the switch cost.
  - **Deliverable** — One backup storyboard and cost note.
  - **Pass condition** — Backup can pause once when playing across the chosen timestamp. Seeking past it never silently pauses the video.
  - **Evidence** — [Pausepoint storyboard, browser crossing and seek proof, and switch estimate](design/PHASE-2.md#pausepoint-backup)

- [x] **020. Freeze the concept scope**
  - **Objective** — Align implementation around one memorable behavior.
  - **Work** — Lock a single source-scoped held place, source resets, ordinary seeking, return and stay. Defer persistent history, accounts, share links, automatic chapters and additional themes.
  - **Deliverable** — Signed-off behavior and scope brief.
  - **Pass condition** — Every required feature maps to the premise or essential player usability. No optional feature blocks core progress.
  - **Evidence** — [Phase 3 concept scope and behavior boundaries](design/SCOPE.md)

## 03 · UX architecture and interaction rules

- [x] **021. Specify the controls layout**
  - **Objective** — Keep the normal player familiar alongside the signature.
  - **Work** — Set video, status shelf, full-width seek and transport order. Place play, time, mute and fullscreen outside the auxiliary menu. Put optional settings after required controls.
  - **Deliverable** — Labeled desktop and compact layouts.
  - **Pass condition** — All five required controls stay discoverable in both layouts, even with an active detour.
  - **Evidence** — [Desktop and compact control layout](design/PHASE-3.md#layout-and-caption-boundary) and [verified control visibility](submission-report/EVIDENCE.md#2026-11-15-phase-3-interaction-proof)

- [x] **022. Write the state transition table**
  - **Objective** — Prevent impossible or misleading detour states.
  - **Work** — Define unavailable, idle, held, returning and recoverable failure. Define source reset, source replacement, stale seek, duration change, ended and disposal events.
  - **Deliverable** — Transition table with allowed inputs and effects.
  - **Pass condition** — Every event has a deterministic outcome. Only successful return or explicit clearing consumes a valid mark.
  - **Evidence** — [Per-instance transitions and outcome table](design/PROTOTYPE.md#behavior-and-failure-boundaries)

- [x] **023. Define a safe origin**
  - **Objective** — Store the true position and media identity.
  - **Work** — Capture unrounded currentTime with a source epoch only for on-demand media supported by host/provider state. Check metadata and, where reported, real seekable ranges. Define how a range changing after mark affects Return.
  - **Deliverable** — Origin contract and guard cases.
  - **Pass condition** — NaN, Infinity, live, nonseekable and stale source paths never create a misleading valid mark.
  - **Evidence** — [Origin contract and guard cases](design/PHASE-3.md#safe-origin-and-seek-mapping)

- [x] **024. Keep the playhead conventional**
  - **Objective** — Maintain the user's expectations when exploring.
  - **Work** — Map seek endpoints linearly to duration on supported VOD. Draw current buffered ranges and one origin mark separately. Keep the origin mark out of pointer hit-testing and tab order.
  - **Deliverable** — Seek mapping and visual roles spec.
  - **Pass condition** — Start and end remain reachable, holding a place changes no seek mapping, and gaps cannot appear buffered.
  - **Evidence** — [Seek geometry and actual range mapping](design/PHASE-3.md#safe-origin-and-seek-mapping) and [Home/End and disjoint-range checks](tests/browser.test.mjs)

- [x] **025. Specify return settlement**
  - **Objective** — Handle latency, error and repeated input.
  - **Work** — Issue one Video.js seek per Return. Use source-matched observed completion, expiry and tolerance. Give pointer/keyboard seek precedence by invalidating the pending return when a later user seek wins.
  - **Deliverable** — Return completion and timeout spec.
  - **Pass condition** — A stale completion cannot consume a newer mark. A failed return retains a valid mark and permits retry or Stay here.
  - **Evidence** — [Settlement and timeout rules](design/PHASE-3.md#settlement-and-playback-intent) and [provider rejection and stale-result tests](tests/browser.test.mjs)

- [x] **026. Set playback continuity rules**
  - **Objective** — Prevent unexpected pause or autoplay.
  - **Work** — Keep ordinary browsing and repeated seeks in the provider's current play/pause mode. At ended, clear ended through the return seek where supported and let Play remain explicit. Document platform exceptions.
  - **Deliverable** — Playing, paused and ended behavior table.
  - **Pass condition** — A paused return remains paused, an active return continues where supported, and ended never triggers autoplay.
  - **Evidence** — [Playback continuity rules](design/PHASE-3.md#settlement-and-playback-intent) and [native paused, playing and ended checks](submission-report/EVIDENCE.md#2026-11-15-phase-3-interaction-proof)

- [x] **027. Review keyboard and pointer paths**
  - **Objective** — Offer every signature action without relying on a gesture.
  - **Work** — Set Tab order and Enter/Space activation. Retain the documented slider keyboard model and click/tap seek. Document pointercancel and a no-drag path. Avoid page-global shortcuts for signature actions.
  - **Deliverable** — Input map and focus return rules.
  - **Pass condition** — Both detour outcomes are reachable with Tab and Enter. Tap or keyboard can substitute for dragging.
  - **Evidence** — [Input map and focus behavior](design/PHASE-3.md#inputs-copy-and-accessibility) and [keyboard and emulated tap checks](tests/browser.test.mjs)

- [x] **028. Design captions and menus together**
  - **Objective** — Prevent collisions between content and navigation.
  - **Work** — Give caption cues a protected video area. Place the detour row in the control shelf. Define Escape, focus return and menu collisions in inline and fullscreen layouts.
  - **Deliverable** — Caption-safe menu and focus diagrams.
  - **Pass condition** — Two-line captions stay readable with an open detour, and a settings menu can close and restore focus.
  - **Evidence** — [Caption boundary and settings disclosure](design/PHASE-3.md#layout-and-caption-boundary) and [two-line cue and Escape proof](tests/browser.test.mjs)

- [x] **029. Define icon and language behavior**
  - **Objective** — Make controls intelligible with localization and assistive tech.
  - **Work** — Set labels for idle, held, returning, error and disabled states. Announce meaningful transitions only. Format all timestamps with unambiguous time labels and test longer translated copy and RTL text.
  - **Deliverable** — Copy inventory and announcement plan.
  - **Pass condition** — No per-second announcements. Long text wraps without clipping and control names retain their meaning.
  - **Evidence** — [Status copy, time formatting and RTL layout contract](design/PHASE-3.md#inputs-copy-and-accessibility) and [long-copy layout probe](tests/browser.test.mjs)

- [x] **030. Approve the real user journey**
  - **Objective** — Prove the critical paths before styling effort.
  - **Work** — Walk through hold, several seeks, return, stay, source swap and keyboard-only exit on a clickable prototype. Include a state with missing tracks and one disabled time state.
  - **Deliverable** — Reviewed interaction prototype and issue list.
  - **Pass condition** — All six paths complete without rescue. Critical UI ambiguities are fixed or assigned before production styling.
  - **Evidence** — [Interaction walkthrough](design/PHASE-3.md#walkthrough-and-open-checks) and [prototype evidence](submission-report/EVIDENCE.md#2026-11-15-phase-3-interaction-proof)

## 04 · Visual system and motion language

- [x] **031. Set the visual grammar**
  - **Objective** — Give DETOUR an original, stable player identity.
  - **Work** — Use matte graphite, cool off-white text and a safety-yellow held-place accent. Use square joins, a short bent bracket and tabular times. Keep caption surfaces and functional markings legible.
  - **Deliverable** — One-page token and geometry sheet.
  - **Pass condition** — Default and held states look coherent on bright, dark and mixed footage. Held state remains distinguishable without color.
  - **Evidence** — [Palette and geometry](design/PHASE-4.md#tokens-and-geometry) and [dark, mixed and bright boards](design/PHASE-4.md#contrast-and-visual-evidence)

- [x] **032. Set typographic hierarchy**
  - **Objective** — Make playback information readable without crowding.
  - **Work** — Use an open, neutral sans, tabular numerals and readable casing. Keep time, Return and navigation labels distinct. Use one short visual label per action.
  - **Deliverable** — Type stack, scale and text specimens.
  - **Pass condition** — Long timestamps and translated action labels fit at 240 px without ellipsis on the core action.
  - **Evidence** — [Type stack and responsive copy](design/PHASE-4.md#tokens-and-geometry) and [240 px long-copy probe](tests/browser.test.mjs)

- [x] **033. Design the rail and origin mark**
  - **Objective** — Show both positions with one conventional control.
  - **Work** — Draw linear rail, fill, accessible focus style and separate origin notch with an always-readable ticket. Offset or simplify the notch at the ends without moving its true position.
  - **Deliverable** — Rail component visual states.
  - **Pass condition** — Current head and origin at identical, near and far positions remain identifiable. Decorative marks cannot capture input.
  - **Evidence** — [Rail geometry](design/PHASE-4.md#tokens-and-geometry) and [endpoint, near and coincident marker checks](tests/browser.test.mjs)

- [x] **034. Design transport and options**
  - **Objective** — Give the signature room while protecting core controls.
  - **Work** — Set reusable icon, button, hover, pressed, disabled and focus styles. Move rate or secondary actions into a bounded menu only when needed. Keep mute and fullscreen labeled to assistive tech.
  - **Deliverable** — Control family and compact menu drawings.
  - **Pass condition** — Common operations have consistent appearance and pressed state. No essential item disappears behind settings.
  - **Evidence** — [Control family and visible states](design/PHASE-4.md#motion-and-visible-states) and [transport and settings layout checks](tests/browser.test.mjs)

- [x] **035. Build a deliberate responsive system**
  - **Objective** — Scale the player by container width.
  - **Work** — At 240-319 px put the action on its own row with wrapping. From 320 px preserve 44 px signature targets. At 600 px and above align the return ticket beside supporting actions when space allows.
  - **Deliverable** — Container layout grid and breakpoint examples.
  - **Pass condition** — Design fits 240, 320, 375, 768 and desktop widths without overflow, target overlap or clipped focus.
  - **Evidence** — [Container rules at six tested widths](design/PHASE-4.md#container-rules)

- [x] **036. Define motion around the hold**
  - **Objective** — Make the state change visible without screen movement.
  - **Work** — Use a short opacity or transform handoff on the held marker, then keep it fixed. Reserve the shelf size to avoid hunting controls and remove nonessential animation for reduced motion.
  - **Deliverable** — Motion timings and reduced-motion alternatives.
  - **Pass condition** — Transition completes in 160 ms or less, never animates the true playback clock and causes no control displacement.
  - **Evidence** — [140 ms motion and reduced-motion behavior](design/PHASE-4.md#motion-and-visible-states) and [motion/geometry checks](tests/browser.test.mjs)

- [x] **037. Resolve real playback statuses**
  - **Objective** — Keep loading and problems legible within the design.
  - **Work** — Specify real loading, buffering, returning, ended, no poster, error and retry surfaces. Preserve the held label on a recoverable return failure.
  - **Deliverable** — State sheet against two contrasting films.
  - **Pass condition** — Status is distinguishable from a held place, captions remain visible, and unavailable values are represented honestly.
  - **Evidence** — [Status states](design/PHASE-4.md#motion-and-visible-states) and [loading, error and two-fixture proof](submission-report/EVIDENCE.md#2026-11-15-phase-4-visual-proof)

- [x] **038. Define contrast and focus tokens**
  - **Objective** — Make the design robust under common accessibility modes.
  - **Work** — Measure text and component contrast against the opaque shelf. Add a visible outline using only readable system colors in forced colors. Include focus over the darkest and brightest frames.
  - **Deliverable** — Contrast measurements and mode samples.
  - **Pass condition** — Normal text reaches 4.5:1 and relevant UI boundaries reach 3:1. Keyboard focus and origin shape remain visible in forced colors.
  - **Evidence** — [Measured ratios and forced-colors sample](design/PHASE-4.md#contrast-and-visual-evidence)

- [x] **039. Compose player-only views**
  - **Objective** — Prove the player carries the visual idea.
  - **Work** — Prepare wide, narrow and bright-footage concept boards. Crop to the player edge and compare those with and without a held point and visible caption cue.
  - **Deliverable** — Three design boards for internal review.
  - **Pass condition** — Each exposes the actual control hierarchy. A project title, surrounding site or themed footage is unnecessary for recognition.
  - **Evidence** — [Three paired player-only boards](design/PHASE-4.md#contrast-and-visual-evidence)

- [x] **040. Lock the visual acceptance sheet**
  - **Objective** — Give build and QA a shared target.
  - **Work** — Annotate measurements, font, focus, placement, contrast, icon state and motion. Label sketches as design only. Use a single token set and reserve evidence slots for real player captures.
  - **Deliverable** — Buildable acceptance sheet.
  - **Pass condition** — Every critical state has a reference. The build can be compared to explicit size, spacing and behavior checks.
  - **Evidence** — [Visual acceptance sheet and reproducible gallery](design/PHASE-4.md)

  - **Deliverable** — Module map and import boundary checks.

  - **Objective** — Confirm PlayerController and seek behavior before UI investment.

  - **Objective** — Avoid interpreting moving live windows as fixed video.

  - **Deliverable** — Capability table and provider adapter contract.

- [x] **046. Design event and render budgets**
  - **Objective** — Keep the skin lightweight and responsive.
  - **Work** — Subscribe only to time, source and relevant states. Update the marker on state changes and cheap CSS changes. Allow no additional frame decoding, polling, analytics or mandatory third-party fetches.
  - **Deliverable** — Event lifecycle and performance budget.
  - **Pass condition** — Listeners are bounded per instance; no continuous animation loop is needed and state updates avoid whole-player rebuilds.
  - **Evidence** — [Phase 5 package, browser and lifecycle acceptance](design/PHASE-5.md#2026-11-15-phase-5-acceptance)

- [x] **047. Set accessibility ownership**
  - **Objective** — Reuse the proven components for standard playback.
  - **Work** — Keep v10 controls and the documented time slider. Use semantic buttons for hold and return, an existing or scoped menu, and a polite live status for actual transitions.
  - **Deliverable** — Semantic element and focus map.
  - **Pass condition** — Each interactive node has one accessible name and role, and visual decoration is absent from the accessibility tree.
  - **Evidence** — [Phase 5 package, browser and lifecycle acceptance](design/PHASE-5.md#2026-11-15-phase-5-acceptance)
