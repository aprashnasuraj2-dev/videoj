Deterministic/manual investigation and replay do not require web or inference. Model claims are untrusted; exact citation integrity and deterministic replay do not prove empirical truth or independent corroboration.

Browser/peer tests use real Chromium and distinct loopback origins with injected model responses. This establishes candidate behavior, not live commercial inference, deployed HTTPS conformance or public availability of the V2 candidate. The existing public app is legacy and unchanged; no release, merge or deployment is authorized. See [the pre-release checklist](../../docs/sutra-v2/DEVPOST-PRE-RELEASE.md) for unresolved gates.

SUTRA is a debugger for conclusions. Product objective: falsification-first investigative reasoning and reproducibility. Trust/runtime infrastructure: consent, causal integrity, monotonic witnesses, compensation and bounded recovery, as a separate second act. Competition objective: attack a conclusion, expose declared ancestry, compute what survives and a decisive next observation, then verify a portable Proof Capsule offline. No paid inference required.

The primary browser entry is an investigation objective or a clearly labeled synthetic worked example. The older labs remain executable and their evidence markers remain intact.

Isolated from production routes. V2 owns its pinned Vite and Playwright toolchain. Python 3.10+ is required for the independent verifier bundle. From repository root:

```sh
npm ci --prefix apps/sutra-v2
rustup target add wasm32-unknown-unknown
node apps/sutra-v2/build.mjs
node --test apps/sutra-v2/test/build-contract.test.mjs
node apps/sutra-v2/node_modules/playwright/cli.js install chromium
node apps/sutra-v2/test/browser.cjs
```

`build.mjs` is the canonical V2 artifact build. It uses the standalone V2 Vite toolchain, compiles the local Rust support module, builds `apps/sutra-v2/dist`, stages static security headers and a deterministic independent Python verifier zipapp, and refuses an artifact that does not identify as the V2 Knowledge Compiler. It does not deploy anything.

The actual browser graph calculation and mutation are local, with no model or network. The optional scripted planning path exercises the unchanged pinned agent runtime with two local agents; the model can only select a host-approved method, not supply a verdict or code. Two calculations share the assumed beam formula; they differ in whether the section moment is declared or derived. This is not independent scientific corroboration. Export contains exact graph and receipt text, and browser replay is same-kernel. Separate Python reference consumer is tested in CI. No public deployment, physical-device or human accessibility acceptance claimed.

The conflict laboratory uses the locally compiled Rust support lattice through a pointer-free WASM ABI. Only the locally admitted compatibility projection enters the module. The module never fetches a peer or interprets external code. V2 owns its static _headers contract: the wildcard policy permits 'wasm-unsafe-eval' but not JavaScript 'unsafe-eval'. The browser harness consumes the built policy with only a loopback peer exception; an external-script Chromium probe compares actual WASM compilation under the legacy and V2 policies. The Pages candidate adds only its approved guide origin. This is candidate verification, not deployed HTTPS evidence. The build embeds a SHA-256 pin in the application bundle; the loader streams at most 1 MiB, checks the digest and rejects all WASM imports before instantiation. This detects artifact mismatch, not compromise of the entire trusted build. If the module cannot load or disagrees with the existing surviving-world/conflict report, the transition fails closed. The legacy session export is unchanged; support analysis has a separate export, not an independent evidence receipt. No factual authority follows from conditional sufficient supports.

Verify outside the browser using `python3 -I -S sutra-proof-verifier.pyz sutra-proof-capsule.json --pin-file sutra-proof-capsule.sha256`. Trust the verifier independently; the digest distributed alongside it alone cannot authenticate a compromised publisher. CI checks deterministic rebuild and actual browser download bytes, then executes the downloaded verifier from an isolated directory. No deployment is performed.

A separate local operator runner accepts one bounded JSON configuration on stdin. `node apps/sutra-v2/local-council.mjs < config.json` previews exact approved scope and routes without model contact or credential access. Inspect the preview's exact destinations, selected binding descriptors/values, credential environment aliases, deadlines and `planPin`. Only `node apps/sutra-v2/local-council.mjs --execute-local --approve-local-disclosure --approve-plan sha256:... < config.json` permits literal-loopback transport. The digest must be the preview's exact pin; any change, including whitespace, requires a new preview. Add `--export-version` after the pin to include a baseline-compatible living investigation version and its pin when at least two distinct proposals are admitted. This optional local output contains the entire reviewed contract, not only disclosed bindings. Choose your own model IDs, roles and compatible protocols. Config fields: `version: sutra-local-expression-council/v1`, exact `contractText`, `contractPin`, `disclosure: {bindingIds,includeValues}`, `connections: [{id,label,protocol,endpoint,models,authMode,credentialEnv}]`, `agents: [{id,role,connectionId,model}]`, `budget: {maxCalls,maxInputBytes,maxOutputTokens,maxConcurrent}`, `maxRounds`, `maxOutputTokens`, `roundPolicy`, `timeoutMs`, `transportDeadlineMs`. Use `authMode: none` and `credentialEnv: null` for no-key local inference; authenticated routes use an explicitly named `SUTRA_LOCAL_*` environment variable, never a credential in the config. No hosted relay or live commercial provider support enabled.

### Per-agent evidence permissions (candidate)
The optional `disclosure.agentScopes` field contains one `{agentId,bindingIds,includeValues,feedbackFrom}` per configured agent. Binding IDs must be a subset of the top-level envelope, raw values cannot exceed the envelope, and peer feedback is explicitly directed. A recipient may receive peer feedback only from a sender whose entire evidence scope is no broader, including raw-value permission. This prevents deliberate forwarding of a formula selected using additional private inputs. The preview shows actual per-agent binding descriptors/values. Local output can contain all admitted results; shared endpoints, role/question text, timing, global resource and stop signals remain side channels. This is not cryptographic noninterference or provider isolation.

Agent Studio includes a per-agent evidence-permission editor with binding subsets, independent raw value and directional peer-feedback choices. It previews the policy before scoped consent, refuses down-scope flow, invalidates old exports on edits and shows applied permissions beside the trace. The UI still uses local scripted adapters only.

Agent Studio can export an operator config using the selected model IDs, roles, protocol choices, scopes and separate literal-loopback addresses. It uses the same pure preflight as the CLI, shows exact plan pin and CLI commands, and requires explicit full-contract export consent. No browser endpoint contact or credential enrollment. The Node runner re-admits the config before execution; a browser-generated digest is not authentication or permission to skip preview.

## Public release persistence scope
The Pages candidate offers bounded browser network runs; it does not advertise durable hosted research or account-based session recovery. General autonomous research is available through the separate single-operator loopback Node host only. A refreshed browser cannot recover the previous research report or receipt automatically; a disconnected host may still finish a request, and dispatch/billing remain unverified. Export reviewed artifacts with separate retained pins before leaving. Local explicit history files and offline proof exports are separate from hosted research sessions. Public ingress must continue rejecting /api/research/* and resume/report endpoints unless a separately reviewed authenticated storage design, retention/deletion policy, lease/fencing and backup/restore evidence are approved.
