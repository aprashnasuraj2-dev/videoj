# Bounded action recovery model

Two callers share one already approved logical action. Pending deliveries can be lost, repeated by caller or delayed across crash; both can reconcile from the durable ledger. A split effect then ledger write loses volatile staged state on crash. The safe abstraction commits both together and acknowledges only a committed effect. A status miss never makes a caller terminal.

Safe.cfg checks types, at-most-one effect, receipt soundness and atomic ledger correspondence. Unsafe.cfg must violate AtMostOnce, not merely fail to parse. The Python state explorer is a separate finite implementation of the same simplified transition idea; local V2-009 run reached 33 safe states / 128 edges and an unsafe duplicate-effect trace after 50 discovered states / 124 edges. Self-loop crash and duplicate transitions are counted differently by TLC. No liveness, fairness, arbitrary keys, signatures, contact budget, storage rollback, power-loss behavior, or Go refinement proved. Approvals are assumed valid; authorization invariants require a wider model. Mapping: Dispatch/Drop correspond to client dispatch/unknown; Deliver to receiver commit/dedup; Status to reconciliation; Crash to process exit; atomic effect+ledger to signed snapshot replacement and sync under trusted filesystem assumptions. No external effect is modeled.

Run `sh check.sh` on a network-enabled host (Java, curl, SHA256 and Python required). Official release v1.8.0 and GitHub-published SHA-256 are pinned. Never interpret a failed download or syntax failure as a negative-model counterexample.
