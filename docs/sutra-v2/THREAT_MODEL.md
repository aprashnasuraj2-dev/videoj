# SUTRA v2 threat model — executable engineering register

This document defines the current trust boundaries for the SUTRA knowledge compiler, browser runtime, synthetic action-recovery laboratory, inference relay, and planned multi-provider BYOK workspace. The machine-readable source is [threat-model.json](threat-model.json), and CI validates its referenced regression evidence.

## Security posture

The central rule is **data does not become authority by being generated by a model, published by a peer, signed, hashed, or replayed successfully**. Authority comes from a small set of explicitly provisioned host capabilities: exact consent, fixed transports, bounded runtime policy, authenticated action callers, independent witness pins, and quota admission. Each boundary is deliberately narrower than the data it processes.

The strongest current action path is still a synthetic laboratory. A caller-authenticated `SharedAuthority` owns the synthetic effect, receipt ledger and contact budget; an independent pre-effect `AdmissionFence` reserves the authority transition before that local effect; exact grants are checked against a separately witnessed grant-policy head and a returning client pins exact policy ancestry. External success requires the exact fenced authority result plus a fresh challenge-bound fence/policy proof. This narrows cloned-authority and stale-policy races, but **coordinated rollback/provisioning of all retained trust domains remains an executable counterexample**, and lost reservation-owner evidence can make admission fail closed indefinitely. There is no distributed-consensus, public-transparency, arbitrary-external-effect or trusted-time claim.

The inference path is separately bounded. Checked-in configuration keeps inference disabled by default and BYOK false. A fixed same-origin relay validates the request, reserves resources before upstream contact, rejects visitor Authorization and arbitrary provider URLs, and never converts incomplete provider streams into completed results. These controls do not prove provider truth, privacy, billing, or model behavior.

## Principals and authority

| Principal | Allowed authority | Explicitly not authority |
| --- | --- | --- |
| Browser user | Explicit UI choices, consent, future provider/profile selection | Model-generated permissions or verification truth |
| Browser host/runtime | Closed policy, fixed adapters, bounded orchestration | Secret disclosure or implicit widening from peer/model text |
| Model | Proposal generation | Credentials, destination selection, budgets, consent, action keys, proof status |
| Peer publisher | Bounded public graph/data publication | Caller private context, provider key, remote execution |
| Consent approver | One exact scoped approval | General discovery or future unrelated actions |
| Action authority | Synthetic effect/ledger/contact state and expected-head CAS | Distributed consensus or arbitrary external effects |
| Independent witness | Monotonic head and signed freshness attestation | Underlying action authorization or trusted wall-clock time |
| Inference relay | Fixed validated upstream request under server policy | Caller-selected URL/credential |
| Provider | Executes inference under its own semantics | Verification truth or SUTRA policy authority |
| Future credential store | Retain secret values and expose opaque handles | Graph/prompt/peer/trace data |
| Operator | Provision reviewed configuration | Independence when the operator controls every trust domain |

## Critical invariants

1. **Untrusted text is never authority.** Peer/model content cannot select credentials, grant private context, enable tools, approve writes or widen budgets.
2. **Ambiguity never becomes success.** Lost write/provider/witness responses stay unknown until an authenticated reconciliation path resolves them.
3. **External action acknowledgement is two-domain and fresh.** A static authority receipt or static witness view alone is insufficient; a fresh caller challenge is signed by the independently keyed witness after convergence.
4. **Budget admission precedes scarce work.** Ambiguous admitted work is conservatively charged; successful retry semantics never mint fresh authority implicitly.
5. **Secrets are excluded structurally, not by prompt instruction.** Planned BYOK values must remain inside a host-owned secret boundary and be represented elsewhere only by opaque handles.
6. **Rollback claims are relative to a trust root.** Authority-only rollback is detectable relative to the witness; coordinated rollback of both current local trust roots remains outside the guarantee.
7. **Deterministic/no-AI operation remains first-class.** Provider access cannot become a prerequisite for verification kernels or evidence replay.
8. **Orphaned admission is safety-first, not magically recoverable.** If the reservation owner loses durable evidence, the fence does not auto-abort merely to regain availability; a delayed arbitrary external effect could otherwise be duplicated.
9. **Exact ancestry is not fresh provisioning.** A returning client can reject alternate history relative to its retained pin; a newly provisioned client after coordinated rollback has no such independent memory.

## Highest-risk open work

The machine register marks unresolved threats with their dependency gates. The most important open mechanisms are: orphaned-admission availability without unsafe reservation stealing; coordinated rollback and fresh-client provisioning; preventing deliberate custom wrappers or source changes from re-exposing lower in-process write laboratories as approved surfaces; durable expiry/revocation and separate compensation approval; independently operated witness/transparency/key-rotation policy; semantic taint/prompt-injection containment; real BYOK credential isolation against XSS/extensions/dependency compromise; provider-independent reservation/reconciliation; and production abuse controls beyond Origin checks.

No item in this document is a security certification. A threat is not “closed” merely because one regression passes; tests establish narrow executable properties under their stated assumptions.


## V2-013 admission availability evidence

At exact source `a9dd3fc62ad35bd14ec8cd4ebdd35bfac7fcd051`, both knowledge workflows and all auxiliary workflows pass the new admission-availability and finite policy-ancestry gates. The safe availability model intentionally has a liveness counterexample when the reservation owner disappears. The permanent unsafe mutant that steals that orphan reaches two delayed effects and violates `AtMostOneEffect`. This is evidence for a bounded safety tradeoff, not a distributed impossibility theorem or production-side-effect guarantee.

The V2-013 continuation now enforces the accidental mount boundary in the Go API: lower raw authority/post-effect witness/legacy grant effect layers no longer implement `http.Handler`, the strongest anchored composite no longer exports its unpinned `Commit`, `Status` or `ProcessAttested` methods, and legacy write paths are rejected without mutating authority, fence or policy state. This does not prevent a deliberate custom wrapper around lower exported laboratory operations or hostile source modification, so V2-RUNTIME-02 and release security remain open.

## V2-013 network write-surface hardening — e64e35c73f7d

Exact source `e64e35c73f7dcef09d4457a24d9963c1a7deeb73` passed both knowledge workflows and every auxiliary PR workflow. The verified scope is construction safety, not production transaction safety: lower effect layers cannot be mounted directly as `http.Handler`; the current anchored fenced-grant guard exposes only its pinned composite mutation path to external callers; and legacy write route names return rejection with unchanged authority, fence and policy state. Independent fence, authority-witness and grant-policy-witness control planes remain separately hostable because they do not own the authority effect.

Counterexample retained: lower in-process laboratory operations still exist for regression/failure modeling. A developer can deliberately write a new adapter around them or modify source, and the synthetic composite still does not establish arbitrary-provider exactly-once effects, physical power-loss safety, independent provisioning, coordinated-rollback resistance or orphan liveness. The hardening closes an accidental API/deployment bypass; it does not close V2-RUNTIME-02.


## T24 — false permanent non-application closure

V2-013 adds a narrow availability recovery contract for pre-effect orphans. The proof is intentionally stronger than a status lookup: a separately keyed authority must attest that the exact reservation/idempotency identity is **permanently closed without application**. The proof binds the signed reservation hash, request hash, authority before/after heads and random admission token, and its verification key cannot equal the action-authority or fence key.

The strongest counterexample is retained rather than hidden. If that closure authority lies after the old identity was dispatched, the fence can be cleared, a second identity can be admitted, and the delayed old plus new effects can both arrive. TLC and an independent Python explorer both preserve this AtMostOneEffect violation. Therefore signature validity is not enough: provider semantics and independent operation of the closure authority are part of the trust boundary. Current tests use a synthetic key; no real provider/upstream closure guarantee is claimed.
