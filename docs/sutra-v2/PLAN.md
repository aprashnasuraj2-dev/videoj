# Outcome-driven engineering plan

## Goal and threat model

Open agentic-web verification, not a general chatbot or an assertion of universal truth. A valid signature/hash does not imply truth, agreement does not imply independence, an internally successful computation does not establish applicability, and a valid mathematical statement does not prove an informal interpretation. Model output, peer metadata and supplied results are untrusted. Keep caller-controlled contact permission, actual browser agent execution and bounded local verification. Prove technical advantages against ordinary LLM, self-critique, multi-agent debate and tool-calling baselines with matched budgets and frozen cases. No claim of world-first without bounded prior-art search; describe exact differentiating combination.

## Architecture and workstreams

1. Migration audit; immutable baseline and isolated v2 branch.
2. Closed claim intermediate representation, assumptions and verification obligations; human-reviewed compilation.
3. Canonical content identity, artifact version selection and publisher identity distinct from truth.
4. Dependency DAG, bounds, cycles, reverse index and resource budgets.
5. Deterministic verification kernel; explicit computed/refuted/incompatible/indeterminate/blocked states.
6. Assumption algebra: units and conversions, ranges, population, scope, boundary conditions.
7. Incremental verification and measured invalidation/reuse; no untrusted receipt cache.
8. Mathematical proof/counterexample: restricted exact proof first; separately pinned formal toolchain with replay boundary.
9. Engineering/physics: actual equations, dimensional compatibility and sensitivity; no professional certification.
10. Scientific evidence: provenance, source version, support/contradiction, retraction and evidence lineage.
11. Statistics/medicine: effect-size reproduction and population applicability; research-only, not medical advice.
12. Capability discovery: conforming agent manifests with separate typed verification capabilities.
13. Real cross-origin browser execution through existing pinned runtime and consent; no simulated external adoption.
14. Security/privacy: hostile publisher, forged evidence, tampering, replay, budget and disclosure adversaries.
15. Product workspace: inspect, compare, challenge, revise and replay, keyboard/mobile/a11y.
16. Portable reports and independent implementation, not replay calling same library.
17. Open Verification Kit, external publisher trial.
18. Frozen benchmark and fair comparisons; 200 initial cases proposed, separate held-out split, report uncertainty and failures.
19. Public candidate: challenge conformance, privacy, capacity, accessibility, approved judge inference route or valid alternative, isolated deployment.
20. Competition package: genuine demonstration, actual public URL, free judge path, report; no submission until authorized.
21. Prior-art register: claim, exact comparison, demonstrable distinction and counterexample.
22. Machine-readable capability contracts: scope, expected behavior, challenge, evidence, invalidation rule.
23. Recursive self-verification: agent generates proposals; independent deterministic oracle certifies observations.
24. Mutation/adversarial laboratory with fixed tests and authorized synthetic faults.
25. Actual HTTPS deployment validation: fresh browser, CORS/cache/route checks, no mock substitution.
26. Observatory: public reproducible observations linked to revision, deployment, raw evidence and failures.
27. Independent consumer and independently operated peer trial; same-owner origins not independent adoption.
28. Final falsification/novelty audit; reproduce flagship demonstrations and state failures.

## Flagship demonstration sequence

A. Real exact computation and assumption mismatch; refute a convincing but incompatible conclusion.
B. Evidence revision changes downstream outcomes, preserving unaffected computations; measure calculation reuse separately from total latency.
C. Publish a claim artifact and independently reproduce it across origins; unknown compatible peer discovered under consent.
D. Demonstrate one cross-disciplinary composition with explicit source applicability, evidence lineage, and at least two alternative methods.
E. Turn the kernel onto SUTRA's own capability contracts; introduce authorized synthetic fault and detect it from the actual deployed website, exporting a reproducible observation.

## Delivery order

Prioritize a deeply integrated narrow domain slice, then broaden. By late November build kernel + self-challenge; early December cross-origin proof capabilities and independent replay; mid December engineering/math + scientific/statistical evidence adapter and UX; late December Observatory, trials and benchmark; early January approved candidate and submission materials. Dates are targets, not promises. Confirm official rules/deadline before release. Existing release gates remain: no paid inference, production/DNS changes, or publication without applicable authorization and evidence. Deployment validation is a required later capability, not permission to skip gating.

## V2-003 priority shift: counterfactual evidence frontier

Conformance, orchestration, source receipts, deterministic computation and self-testing are foundations, not the competitive thesis. Prior art: [de Kleer ATMS (1986)](https://doi.org/10.1016/0004-3702%2886%2990080-9), [proof-carrying data](https://dspace.mit.edu/entities/publication/6cf95695-f0ce-468e-8d8f-16e6033511e9), [assume-guarantee contracts](https://doi.org/10.1016/j.scico.2014.06.011), [proof-carrying agent actions](https://www.nature.com/articles/s41598-026-74900-x), [provenance semirings](https://provsql.org/docs/user/semirings.html). No world-first claim. Build on these concepts, not a new name for them.

Signature workflow: agents publish alternative executable models, explicit assumptions and evidence/observation capabilities. Caller verifies each candidate, retains opposing outcomes, finds minimal incompatible assumptions and shared evidence lineage, then computes a cost-aware observation policy that can resolve a decision across admissible worlds. It must return a concrete indistinguishability witness when available observations cannot discriminate. Observations are proposals, not automatic physical/clinical actions. After authorized real observation, prune inconsistent worlds and revalidate only affected artifacts. Separate finite-model completeness, measurement uncertainty, formal correctness and source truth. Initially finite deterministic worlds, no probability or universal completeness; then interval/contract support and checked observation admission. Treat unknown applicability or missing worlds explicitly, not as false.

Competitive gate: previously unknown compatible peer offers a typed observation with cost and partition contract; caller independently checks what it can, rejects a misleading or redundant capability, and recomputes the contingent policy without a publisher-specific integration. Demonstrate a decision that is not resolved by more agent votes. Show actual receipt lineage, optimality oracle and a failure/abstention. Public Observatory independently challenges deployed behavior after authorized deployment. Separate algorithmic results from live observations and external adoption. Avoid building arbitrary domain count before this end-to-end vertical slice.

## V2-004 — Integrated investigative learning product

User direction: reunite v1 evidence-linked learner with the v2 Evidence Frontier rather than maintain two disconnected product concepts. Core experience: predict → compare executable alternatives → select decisive evidence → inspect time-indexed source → revise explanation → export replayable evidence and remaining uncertainty. The learner becomes the accessible human-facing interface for the scientific investigation engine. Research mode and teaching mode share one knowledge boundary; avoid separate answer authority or duplicate runtime. Existing v1 source integrity, receipt validator, source registry, consent and pinned agent runtime are directly reused. Preserve legacy app and deployment routes. First slice resolves a catalog metadata question against the original synthetic timing fixture; it is not proof of an observed event, real educational efficacy or a rights-cleared course. Next: rights-cleared actual lesson with competing explicit models and guided questions; agent-published observation capabilities with scope, cost and lineage; independently reproduce learner evidence and measure learning transfer versus answer-only and transcript-only baselines. Avoid optimizing time-on-page or equating correctness of prediction with learning. Defer medical intervention claims and real-world safety decisions to appropriately scoped human review.

## V2-005 — First substantive cross-disciplinary lesson and open observation discovery

Original illustrative Simpson's paradox exercise: two possible subgroup tables reproduce aggregate A 80%, B 60%, but equal-weighted standardized comparisons disagree. The caller derives observation partitions from executable local graphs, not peer-declared outcomes. An independently hosted data-only agent network advertises a scoped node and declared effort; existing manifest/graph consent loader and pinned browser runtime execute its leaf adviser under a scripted driver. A compatible cheaper capability can change the policy; a redundant aggregate cannot; forged authority refuses. The actual decisive value is read from a host-pinned original synthetic source, not the publisher. Preserve separation between scope compatibility, calculation, source truth and causation. Transfer question checks interpretation, not measured learning improvement. Next: generalized observation source admission with separately anchored publisher evidence, noise and world completeness, true independently operated publisher and live-model planning under approved bounds, multi-browser/HTTPS Observatory. Do not claim that the finite planner or Simpson's paradox is novel; demonstrate their integration with the open web.

### Knowledge resilience: common-source withdrawal

Multiple adviser networks are not independent evidence if they all point to the same host-pinned table. Simulate that source becoming unavailable: all dependent observations disappear, verified conditional worlds remain, opposing conclusions return to unresolved, and historical receipts must never be displayed as current authority. Re-enable source availability only as an explicit action; require a new observation to resolve. This is a fixed single-source exercise; generalized lineage DAG, revocation provenance, evidence versioning and independently operated publishers remain open.

### Generalized evidence session — finite host-approved profile

Separate a publisher's claimed observation capability from the actual independently pinned source value. A data-only finite session verifies world graphs, exact observation dimensions and normalized rationals, source scope, version and digest; maintains active evidence across explicit source/lineage withdrawal and restoration; computes surviving worlds and next policy; and returns minimum-cardinality conflicting observation IDs when no world survives. Equal declared lineage does not imply genuine independence; multiple copies cannot erase contradiction. The source pins are supplied by a trusted caller, not self-certified by remote data. Bounded to 12 worlds, 8 offers/sources, 24 events; no noisy measurements or arbitrary graphs as domain truth. Later integrate general session into cross-origin discovery and Observatory; build independently implemented replay and held-out adversarial benchmarks.

Browser conflict lab presents the generalized session via explicit reads/withdrawal/restoration, exports actual case/events/result. It does not treat the chosen next observation as a prohibition on learner exploration; all admitted source reads are allowed, and contradiction is explicit. Preserve the shared JSON parser cap (262144 characters for entire event log) and reject unpaired surrogate source bytes before digesting.

## V2-007 — Language boundaries and observed-history/support contracts

Use languages for their semantic or deployment advantages, not portfolio breadth. Go: dependency-free offline Ed25519 witness/consumer, bounded JSON parsing, external anchor and deterministic event history; no claim that a signature proves truth or completeness before first observed checkpoint. Two signers with a cloned anchor can sign divergent children; a separately pinned head rejects the wrong branch but does not stop equivocation. Future durable atomic compare-and-set witness, explicit TLA+ safe/unsafe model and implementation concurrency/crash tests. Rust: bounded native support lattice, no unsafe core, cardinality-first subset closure, conditional sufficient supports exclude empty surviving-world set; <=64 worlds/16 observations native, <=12/8 browser ABI. With n observations, closure work O(n*2^n) and O(2^n) working memory before output; declared budget counts subset evaluations, not wall time. Local WASM is built from source, pointer-free ABI, zero imported modules, build-pin digest and bounded fetch, no arbitrary peer execution. Same trusted build may still be compromised; review deployed CSP and artifact identity. Independently reproduce actual Rust browser outputs in Go against separately frozen binary lesson and exact matching history; not arbitrary graph replay.

Lean 4 is appropriate for the mathematical support soundness/completeness obligations and theorem applicability, TLA+ for state-machine safety before multi-client witness; pin and test toolchains before claiming either. OCaml/Haskell may be appropriate for a typed claim compiler if an actual IR/type-system advantage is demonstrated. Elixir/Erlang may be appropriate for fault-tolerant publisher supervision if an actual distributed process workload emerges. Zig may be appropriate for constrained native/WASM or cross-compilation boundaries where Rust/Go are inadequate. Do not add these runtimes merely for novelty. Preserve existing browser JavaScript and independent Python reference gates rather than rewrite working infrastructure without a measurable reason. No new paid services or production changes.
