# Caller-pinned finite investigations (candidate)

Provide exact UTF-8 case JSON, its independently retained SHA-256 digest, and exact event JSON. The browser example is synthetic; its included pin is a reproducibility convenience, not an external authenticity claim. For your own case, obtain the expected digest separately. The browser text fields normalize line endings, so a different byte sequence fails the pin.

Existing evidence-session v1 schema: `version`, `decisionId`, `scope`, `costUnit`, `worlds`, `sources`, `offers`. Worlds supply exact quantity graph text and a constraint ID; sources supply ID, version, digest and declared lineage; offers select an observed graph node, source, cost and dimension. See `packages/sutra-knowledge/pinned-investigation.js` for the six-world example. Event types are read, source withdrawal/restoration and lineage withdrawal/restoration. A restoration does not restore a historical read. The adapter enforces existing bounds (12 worlds, 8 sources, 8 offers, 24 events) and 256 KiB UTF-8 per input. At most 256 root subsets are enumerated. An unresolved computation cannot imply a decisive state. A contradiction cannot imply vacuous support. Inclusion-minimal repairs are counterfactuals, never automatic actions; a larger inclusion-minimal repair must not be omitted merely because another repair removes fewer roots. Source lineage is declared, not discovered. A policy outcome ID such as `value_0` is not the numeric observation; the export provides exact rational outcome mapping.

Export preserves exact case/event text and result. Verify with `python3 packages/sutra-knowledge/reference/verify_pinned_investigation.py export.json sha256:<independently-retained-case-pin>` from a trusted compatible repository checkout. This is independent deterministic replay, not an outer capsule integrity or freshness proof. The case pin does not bind the event history; a different valid event history can be reconstructed. The original fixed-case Proof Capsule and standalone archive remain separate and unchanged. No external contact or paid inference is required.

## Strict aligned workspace profile

The browser now uses `sutra-aligned-investigation/v1`: all declared worlds must share the same typed graph structure, target ID, input basis and dimensions. Only input values may differ. The schema digest excludes input values and normalizes node order, but preserves operation and argument order. A separately re-pinned mixed-equation case is refused by the strict profile. Legacy generic `sutra-pinned-investigation/v1` reports remain independently replayable; they do not make the alignment claim. The Python reference supports both versions. Structural equality does not certify empirical or semantic validity. The same case/history integrity limits still apply.

## Portable aligned Proof Capsule candidate

The strict profile now has a separate exact-byte capsule, `sutra-aligned-proof-capsule/v1`, up to 256 KiB. Keep the expected case digest and snapshot digest independently of untrusted capsule bytes. The case digest commits to the finite model; the snapshot digest commits to exact case/event text, alignment and full replayed result. Verification independently reconstructs the entire result and alignment. Import does not mutate the live investigation. The browser's export requests a download; it does not certify disk save. The independent offline archive supports `python3 -I -S sutra-proof-verifier.pyz aligned.json --aligned --pin-file snapshot.sha256 --case-pin sha256:<trusted case digest>`. The default fixed-fixture CLI remains unchanged; there is no format fallback. A valid historical snapshot with its own pins remains verifiable. Replacing both trusted pins with new pins for a valid alternate model/history is not detected by this contract. The archive itself must be obtained through a trusted channel. Oversized capsules are refused; no evidence is truncated. Candidate pending exact CI.

The aggregate capsule bound is 262144 bytes, matching the existing strict parser. The first 1 MiB candidate failed exact CI and was corrected rather than widening the shared parser. Individual valid inputs may still exceed the combined capsule budget and are refused without truncation.

## Competing proposal challenge (candidate)

A proposed agent history is untrusted JSON with exactly `caseDigest`, `eventText` (the serialized event array), and `claimedState`. The case pin must be identical to the current case. Replay validates every observation and withdrawal; the asserted state is compared against the computed state, not used as evidence. Compare the two histories' common initial events and recomputed prefix, their final shared and branch-only readings, declared roots, availability, survivors and minimal sets. The histories are not merged or adopted. A correct proposal is not proof of agent identity or factual truth. Independent replay: `python3 packages/sutra-knowledge/reference/verify_proposal_challenge.py diagnosis.json sha256:<trusted case digest>`. Candidate pending exact CI.
