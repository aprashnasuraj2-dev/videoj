# SUTRA judging-evidence scorecard

Conformance is treated as a **separate pass/fail prerequisite**. A polished product that fails the required browser/public-artifact/privacy contract is not rescued by subjective quality. Conversely, passing conformance does not establish product quality.

No organizer numeric score or win probability is invented here. The four published judging criteria receive equal planning attention.

| Judging criterion | Visible artifact / mechanism | Executable or observed evidence | Current gap that must remain visible |
| --- | --- | --- | --- |
| **Technological implementation** | Browser-local graph runtime, exact peer resolution, caller-owned inference, bounded source tools, consent inspector, byte-bound evidence | Runtime/peer/security suites; Chromium/Firefox/WebKit desktop matrix; exact source receipts; failure/cancellation tests; publication inventory | Live funded provider, independent public HTTPS interoperability and final release conformance remain open |
| **Product design / coherence** | Learner-first path: find source → compare → preview/save reviewed reference; developer labs after core task | Hero browser journey, native media seek, keyboard/narrow-screen checks, denial preserves local learning, explicit uncertainty states | Fresh-viewer and physical/human accessibility acceptance remain open |
| **Potential impact** | Reusable evidence validator, consent inspector, starter/Open Kit; manual transcript baseline for learner value | Clean-host/reusable-tool project tests; paired engineering direct-vs-delegated benchmark | No target-user pilot, manual-vs-SUTRA participant result or outside-builder adoption yet |
| **Idea quality** | Non-obvious boundary: zero-model retrieval where sufficient + portable guide composition where useful + evidence remains independently inspectable | Direct path removes unnecessary orchestration while preserving exact-cue results; comparison refuses false agreement; peer metadata cannot choose caller model | Real content semantic usefulness and human-reviewed comparison remain unproven |

## Conformance prerequisite

Before any quality narrative is treated as submission-ready, the candidate must have current evidence for:
- valid public manifest/network/link artifacts and exact named resolution;
- actual browser graph execution rather than a server-only chatbot;
- caller-local peer execution and caller-owned model policy;
- consent before unauthorized external contact;
- bounded execution, malformed/cycle/limit refusal and truthful incomplete states;
- no credential exposure or peer model override;
- working free judge path;
- required public site/demo/materials at the exact candidate revision.

Any critical failure above blocks release regardless of progress percentage.

## Achievement-to-evidence discipline

| Claim family | Minimum evidence before wording it as achieved |
| --- | --- |
| “Finds the exact lesson moment” | Catalog-matched cue + exact source/media identity + actual native seek observation |
| “Compares video and guide” | Separate source records with inspectable excerpts/versions; disagreements preserved |
| “Safe external composition” | Denial produces zero contact; approved destination exact; caller credentials/model policy not delegated |
| “Faster/better for learners” | Paired participant result versus manual baseline; engineering microbenchmarks are insufficient |
| “Reusable by the community” | Clean package plus outside-builder trials; same-owner demos are insufficient |
| “Works on mobile/accessibility” | Physical-device and human assistive-technology evidence where claimed |
| “Affordable/reliable” | Actual provider tokens/cost and dated run sample; synthetic quota tests alone are insufficient |

## Idea mechanism in one sentence

**SUTRA separates retrieval, interpretation, provenance and action authority so an agentic learning experience can compose external capabilities without converting model confidence into evidence or permission.**

That is a mechanism claim. It is not a uniqueness claim.

## Counterevidence policy

Manual-search wins, failed held-out cases, browser failures, reviewer disagreement, untested hardware and provider outages are retained. Negative evidence changes the scope or claim; it is not deleted to improve a scorecard.
