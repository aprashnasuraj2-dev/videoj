# SUTRA prospective acceptance baseline

**Status: prospective targets, not achieved results.**

This baseline consolidates the original 100-phase plan and the current evidence policy. Passing a target later does not retroactively validate a different revision. Failed targets remain reportable results.

## Core hero success definition

A successful hero journey requires all of the following on one recorded candidate revision:
1. Viewer reaches an exact source-backed cue or receives an explicit unsupported state.
2. Any displayed receipt matches the active source/media version.
3. Native media seek reaches a validated cue within ±1 second when playable media is available.
4. Written and video evidence remain separate; conflict/missing evidence is not blended into agreement.
5. Any external peer/MCP contact occurs only after explicit applicable consent.
6. User sees the exact review payload before local save; completed/rejected/unknown outcomes are truthful.
7. No personal credential, private prompt or unrelated browser storage is exposed.
8. The core path remains usable after peer denial and without optional model inference.

A model-generated answer alone is not success.

## Security gates that block public release

Release remains blocked by any current evidence of:
- credential/canary leak;
- consent bypass or external contact after denial;
- peer/router override of caller model policy;
- unbounded graph/cycle/model-call behavior;
- ambiguous write reported as complete or replayed automatically;
- fabricated/altered source reference accepted as evidence;
- stale graph/media silently treated as current;
- uncontrolled paid spend or inability to stop sponsored inference;
- broken default free judge path;
- unresolved critical cross-origin/public-artifact failure.

## Target-change protocol

Numerical targets are not edited in place to match outcomes.

A change requires:
1. a dated decision entry before the affected final measurement;
2. old target preserved as historical;
3. reason classified as scope/rule/method change rather than performance outcome;
4. affected cases/runs identified;
5. a new version/date for the baseline;
6. final reporting shows both the original and revised target where material.

A poor result is not a valid reason to lower a target retroactively.

## Unknowns kept separate

Not approved/measured here: participant daily availability, provider spend ceiling, actual provider price, real content rights, reviewer availability, physical-device availability, public-hosting headroom and external-builder recruitment. Those unknowns cannot be inferred from engineering progress.
