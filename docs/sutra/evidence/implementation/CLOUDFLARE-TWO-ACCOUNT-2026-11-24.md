# Two-account deployment engineering preflight (2026-11-24)

Development-only observation. CloudflareB connection and Patro connection are distinct. CloudflareB returned zero existing Pages projects; the Patro account owns the active aafnaipatro.com zone. Both proposed exact DNS names (sutra.aafnaipatro.com and sutra-guide.aafnaipatro.com) returned no records. No changes made. Exact-name checks do not establish wildcard route precedence or TLS issuance.

The present learner uses Worker static assets and a Durable Object quota. A direct cross-account Worker Custom Domain is not valid: the hosting account must own the zone. Do not CNAME to workers.dev as a substitute for domain binding. Cloudflare documents custom subdomains for Pages using CNAME after Pages domain association, and Pages Functions service binding to a Worker in the same account. Proposed adaptation: CloudflareB Pages learner and guide; learner /api/* only Pages Function dispatch to private CloudflareB API Worker using a service binding. Keep inference disabled, preserve existing Worker quota and source-tool security; static files must not invoke Functions. Both custom hostnames remain in Patro DNS via DNS-only CNAME after origin/domain association. This is a design candidate, not yet tested; verify source-tool asset access, request origin/client identity and header semantics, CORS, CSP, TLS, route precedence, rollback and account billing before promotion. No change to root/apex, wildcard or unrelated routes. Human-dependent checks remain open; no release authorized.

References: https://developers.cloudflare.com/workers/configuration/routing/custom-domains/ ; https://developers.cloudflare.com/pages/configuration/custom-domains/ ; https://developers.cloudflare.com/pages/functions/bindings/ .
