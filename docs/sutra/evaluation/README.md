# SUTRA engineering evaluation, v1

This versioned dataset is a **development regression set**, not the planned 40-case held-out human-reviewed evaluation. It is public to the implementation and may not be reused as independent semantic validation. The one synthetic timing cue gives ten literal matches and ten deliberate zero-match requests; ten comparison adversarial cases require abstention. No external claims are evaluated.

Run `node --test tools/sutra-evaluation/baseline.test.mjs` and `node tools/sutra-evaluation/baseline.mjs` from the repository root. The direct path uses the deterministic source catalog; the delegated path uses the actual restricted runtime, actual source-MCP contract and real Worker request handler in-process with an explicit scripted model. No external transport, real model tokens, provider spend or semantic judgment. Both paths receive the same literal query. Model call counts are orchestration steps, not a quality metric. Direct and delegated elapsed times are same-process laboratory measurements, not browser/network or production latency.

Metric definitions for a future held-out run: exact-cue accuracy = cases with the exact expected cue-ID set / all cases, including abstentions; citation validity = independently catalog-matched emitted citations / all emitted citations (report undefined if none); supported-claim precision = human-reviewed semantically supported atomic claims / all non-abstained atomic factual claims (report undefined if none); abstention recall = correct abstentions / all unanswerable or unresolved cases. Report answerable coverage and false abstention separately to avoid rewarding a system that always refuses. The synthetic test only measures exact retrieval and policy outcomes; semantic precision remains null. Version later changes by adding a new dataset, preserving previous failures and expectations, and documenting rationale. Human review, real corpus rights, live provider and held-out split remain open.
